# Коректор українських речень

CLI-застосунок: приймає речення, через локальну модель (Ollama, OpenAI-сумісний API) виправляє орфографічні й граматичні помилки, стрімить відповідь і показує список змін на рівні слів (`допомагу → допомогу`). Якщо відповідь схожа на переписане речення чи пояснення, застосунок попереджає.

## Запуск
1. Встановіть [Ollama](https://ollama.com/download) і завантажте модель: `ollama pull qwen3:1.7b`
2. Створіть модель із контекстом 2048 (оптимальна конфігурація, див. нижче): `ollama create qwen3-corrector -f Modelfile`
3. `pip install openai`
4. Запустіть:
   - `python app.py "Дякую за допомагу."` — одне речення;
   - `python app.py` — інтерактивний режим;
   - `python app.py --file sentences.txt` — по одному реченню на рядок.

Перевірка якості на 10 тестових реченнях: `python quality_check.py --label after` (результат у `quality_after.md`).

## Яку конфігурацію обрано і чому
Модель: **`qwen3:1.7b` (Q4_K_M)** у **Ollama**. Її я порівняв у двох конфігураціях на ноутбуці (i3-1005G1, MX330 2 ГБ, 8 ГБ RAM; `bench_results.csv`): `before` (налаштування за замовчуванням) і `after` (контекст 2048 токенів). Обрано **`after`**:

| Показник | before | after |
|---|---|---|
| 1 клієнт: tokens/s | 11.9 | **16.3** |
| 1 клієнт: TTFT p95, с | 1.22 | **0.46** |
| 4 клієнти: TTFT p50, с | 73.99 | **22.39** |
| 4 клієнти: tokens/s на користувача | 5.6 | **15.9** |
| 4 клієнти: throughput, tokens/s | 5.2 | **15.0** |

`after` кращий майже в усіх показниках; єдине виключення: на рівні 2 клієнтів в `after` був один запит із помилкою. Застереження: кожен рівень виміряно один раз, а розкид між запусками великий (два запуски `before` дали для одного клієнта 16.5 і 11.9 tokens/s), тож для одного клієнта виграш у швидкості в межах розкиду. Але `after` не гірший, а при кількох клієнтах стабільніший. Застосунку вистачає контексту 2048 (≈550 токенів разом із відповіддю), тому більший контекст нічого не дає, а лише забирає VRAM. Відповідь коректора коротка, тож при ≈16 tokens/s речення виправляється за кілька секунд. Якість на 10 тестових реченнях для `before` склала 6/10: модель не псує правильний текст, але пропускає частину помилок.

## Параметри генерації
- **temperature = 0.** Коректура має бути детермінованою: одне речення дає одну відповідь, творчість не потрібна. Також фіксований `seed`.
- **max_tokens = 256.** Українське речення — це ≈2–3 токени на слово, тож 256 токенів вистачає на кілька речень; водночас, якщо мала модель зациклиться, генерація обірветься приблизно за 16 с (256 токенів при ≈16 tokens/s).
- **Контекст 2048 токенів.** Системний промпт і приклади займають ≈200 токенів, речення ≈100, відповідь до 256, тобто разом значно менше 2048. Зменшений контекст удвічі скорочує KV-кеш і звільняє VRAM (див. 1.5). Задається через `Modelfile`, бо OpenAI-сумісний API не дозволяє змінювати розмір контексту.
- **Міркування вимкнено** (`reasoning_effort: none`): для виправлення речення воно непотрібне й збільшує час у ≈2.3 рази.
- **Системний промпт із п'ятьма прикладами** (few-shot): два граматичні, дві описки й одне правильне речення без змін, щоб модель не «виправляла» правильне. Приклади навмисно відрізняються від тестових речень, щоб не підганяти оцінку якості.

## Обробка помилок
Сервер не запущено, модель не завантажено, таймаут (`--timeout`, 60 с за замовчуванням), порожня або підозріла відповідь моделі: для кожного випадку є зрозуміле повідомлення. Поки модель думає, показується індикатор «Перевіряю», далі відповідь виводиться стрімінгом.
